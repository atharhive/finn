# Extension integration

Entry point: `src/extension/index.ts`, exporting `activate(context)` and async `deactivate()`.

Registers the existing manifest commands `finn.openAgent`, `finn.inlineEdit`, `finn.cancel`, `finn.undo`, `finn.restart`, and webview view `finn.agent`. The inline shortcut is declared by the root manifest. Native editor selection is captured only after workspace-boundary/secret/symlink validation; the prompt uses VSCode's input box. Configuration names match the current manifest: `trueforgeUrl` (default `http://127.0.0.1:8790`), `model`, `fallbackModel`, `contextBudget`, `enginePath`. Empty model, missing workspace, and untrusted workspace have explicit setup states and do not initialize services.

`FinnController` is a pure lifecycle/view-state adapter with an injected `Backend`. It streams actual TrueForge text/status/tool events, assembles context using the actual query and configured budget, includes selected context in the TrueForge prompt, exposes only context metadata in the webview, and drives human accept/reject/undo. Context contents and MCP tokens are never serialized into webview state. Cancellation aborts the run, discards pending proposals, requests upstream cancellation, and ignores late events. Disposal cleans agent, MCP workspace, and Rust context provider. A connection completing initialization after cancellation is disposed immediately.

`view.ts` provides a VSCode-token theme shell with a sea-glass/cyan accent, real transcript/context/review queue, status/error/setup messages, per-hunk actions, keyboard form submission, and no fabricated telemetry. Closed CSP uses a fresh nonce. All model/file content is assigned to DOM textContent, never HTML. The client has no network access or persistent state. `protocol.ts` rejects unexpected message types/fields and oversized strings.

Diff previews use read-only `finn-preview:` documents. The selected hunk alone is applied to the original for the right-hand side, not the entire proposed replacement. Preview storage is session-local. Acceptance and undo reject unsaved workspace editor buffers to avoid overwriting dirty VSCode state. Terminal command requests require an explicit modal `Run command` decision; a dismissed dialog denies execution.

Testing: `npx vitest run tests/extension`. Initial implementation verified 12 tests passing and `node node_modules/typescript/bin/tsc --noEmit` passing. Every pure implementation slice followed a failing test run. Tests cover message validation, CSP/text escaping, configuration, selection path safety, selected-hunk preview, run streaming/context, cancellation/late events, initialization cancellation, disposal, review routing, and mocked VSCode registration/trust gate. Real VSCode host launch and live TrueForge inference are parent-owned integration checks; no provider credentials are available to this worker.
